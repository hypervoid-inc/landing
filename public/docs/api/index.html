Construct Computer site API

Two public endpoints, served from https://construct.computer. The machine-readable version of this page is the OpenAPI 3.1 document, discoverable through the RFC 9727 API catalog.

Conventions

  • Base URL: https://construct.computer. All paths are absolute from there.
  • Requests and responses are JSON. Send Content-Type: application/json on writes.
  • Errors carry { "error": { "code", "message" } }. Branch on code, never on message.
  • Request bodies are capped at 8 KiB.

GET /api/health

Liveness check. No parameters, no storage reads, safe to poll. Responds 200 with application/health+json. 

curl https://construct.computer/api/health

{
  "status": "pass",
  "serviceId": "construct-computer-site-api",
  "description": "Construct Computer site API"
}

POST /api/beta-signup

Records an email address against the call to action that produced it. Every call needs a Cloudflare Turnstile token minted on construct.computer for the beta_signup action, so this endpoint is only usable from the site itself. It is listed here for completeness and for automated discovery, not as an integration point. Submitting an address that is already on the list returns the same 200 and creates no duplicate.

Request body

Field Type Required Notes
email string yes Max 254 characters. Trimmed and lowercased.
name string no Optional. Forwarded to Listmonk only (not stored in D1).
ctaSource string yes Which call to action produced the signup, for example hero or nav.
referral enum no One of twitter, reddit, hackernews, producthunt, linkedin, discord, other. Defaults to other/newsletter when omitted.
referralOther string conditional Required when referral is "other". 2 to 120 characters.
turnstileToken string browser Turnstile token for browser posts. Server ingest uses SIGNUP_INGEST_SECRET instead.
honeypot string no Bot trap. A filled value is accepted and dropped.
meta object no Allowlisted attribution (subscribedVia, authProvider, constructUserId, campaign/utm fields) → Listmonk attribs when API credentials are set.

Response

{ "ok": true, "listmonk": true }

listmonk is false when D1 saved the signup but Listmonk sync failed (retry-safe for authenticated ingest). Browser UX still treats HTTP 200 as success.

Errors

Status Code Meaning
400 invalid_request The body was not JSON, or it failed validation.
403 origin_rejected An Origin header was sent and it was not construct.computer.
403 verification_failed The Turnstile token was missing, stale, or issued elsewhere.
405 method_not_allowed The endpoint was called with the wrong HTTP method.
413 payload_too_large The request body was larger than 8 KiB.
415 unsupported_media_type Content-Type was not application/json.
500 internal_error Verification or storage failed. The request was not recorded.

Discovery

  • /openapi.json, the OpenAPI 3.1 description
  • /llms.txt and /llms-full.txt, product context for models
