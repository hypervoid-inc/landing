## Why choose Construct over a coding agent?

- **One agent for the whole job, not just the code.** Construct triages email, researches, updates a CRM or tracker, and still has a sandbox terminal for the scripting in between.

- **Memory you can read and fix.** Inspect what the agent knows about your customers and procedures, correct it, or forget it.
- **A team workspace, no seats.** Owner, Admin, and Member roles with no member limit, and the agent answers on the web, in Slack, Telegram, Discord, and by email.

## Different definitions of done

For a coding agent, done is a reviewable change: a branch, a diff, a test run, a pull request description. The repository is the context, and CI is the feedback loop.

For Construct, done is a completed outcome: a file saved, a message sent, a record updated, a summary posted, and sometimes code. Most business work looks like this, which is why a small team gets more out of a generalist than a specialist that only finishes the middle of the job.

### Parallel work beyond software delivery

Construct delegates bounded subtasks to temporary agents and combines their results. Lite runs 2 background jobs at once, Starter 4, and Pro 8; additional jobs queue until a slot frees up.

## A scenario that crosses the line

A customer reports a bug by email. The full job is: understand the report, reproduce it, fix it, tell the customer, and log it for the team.

Construct takes the whole span around the code: triage the inbox, extract the report, log the issue in your tracker, draft the customer reply, and schedule a follow-up for when the fix ships. If your team already uses a coding agent for the repository change, Construct hands it a clean, logged issue and handles the communication on both sides.

## Already using a coding agent? Add Construct in 15 minutes

Keep your coding agent on the repository. Give Construct the intake and follow-up around it.

1. **Start on Lite for $9, or take the 7-day Pro trial** for longer runs and your own model keys.
2. **Write the routine down** as instructions, such as "check the support inbox each morning, log bug reports in Linear, and draft a reply to each customer," and paste it into a Construct chat.
3. **Connect the apps** the job needs, such as your tracker and GitHub, from the integration catalog.
4. **Run it once and check the result** in Files and the tracker.
5. **Put it on the Calendar** so it runs every morning with your laptop closed.

There is no import from coding agents; write your conventions into the first instruction and Construct saves them as memory you can read. Two things to set up deliberately: each sandbox command runs for up to five minutes, so keep long builds and test suites in your CI; and workflows do not pause for approval yet, so ask for customer replies as drafts and send them yourself.

## When might a coding agent still fit?

- The whole job is software engineering inside a repository.
- Everyone who reviews the work is a developer.
- Success is defined only by a tested, reviewable pull request.

For the email, research, scheduling, and app updates around engineering work, Construct is the better fit.

Choose Construct. It starts at $9, covers the email, research, CRM, schedule, and code in one job, and leaves results that non-engineers can review. If you already have a coding agent, keep it for the pull request and add Construct for everything around it.
