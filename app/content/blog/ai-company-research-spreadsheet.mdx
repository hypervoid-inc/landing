To research a list of companies into a spreadsheet with AI, give the agent the list, a fixed set of columns, and one rule: every fact needs the URL of a page it actually read, and a fact it cannot find is written as "not found". Run three companies first, check the links, then run the rest in saved batches and finish with a gap report. In Construct the result is a CSV in Files with a source column beside each fact, built by an agent that fetches pages and saves each batch as it goes.

The prompts below do this in seven steps. One trap is worth knowing before you start, because it is where AI research most often goes wrong on prospect lists: pricing pages.

## The pricing-page trap, in a worked example

To show the format, we filled three rows by hand on 2026-10-26 using exactly the rules in step 2, reading each company's pricing page as plain fetched text, the way an agent's page fetch sees it. These rows are ours, not output from a Construct run.

<ArticleTable caption="Three rows filled by hand on 2026-10-26 with the step 2 rules, from each company's pricing page">

| Company  | Pricing model | Lowest paid price in the page text | Billing stated  | Price billed monthly | Free plan | Source                                                   |
| -------- | ------------- | ---------------------------------- | --------------- | -------------------- | --------- | -------------------------------------------------------- |
| Linear   | Per user      | $10 per user/month                 | Billed yearly   | not found            | Yes       | [linear.app/pricing](https://linear.app/pricing)         |
| Calendly | Per seat      | $10 /seat/mo                       | Not stated      | $12                  | Yes       | [calendly.com/pricing](https://calendly.com/pricing)     |
| Airtable | Per seat      | $20/user/month                     | Billed annually | not found            | Yes       | [airtable.com/pricing](https://www.airtable.com/pricing) |

</ArticleTable>

All three pages lead with the annual-billing price. Calendly's text shows "$10 /seat/mo" without saying so; its $12 monthly figure sits behind the **Billed monthly** toggle, in the page's data rather than its visible text. A research run that copies the first price it reads would record $10 for a customer who pays $12. Linear's and Airtable's monthly prices were not in the page at all, so the honest cell is "not found".

That is why the column spec in step 2 asks for the billing period beside every price, and why the rules tell the agent to switch a billing toggle in the browser rather than trust the fetched text.

## What you need

1. **A Construct plan.** Any plan works. Each round of tool calls, such as searches, page fetches and file writes, is a step: Lite allows 50 steps per task, Starter 150 and Pro 1,000 ([pricing](/pricing/)). Batches of ten companies fit any plan.
2. **The list.** A CSV, a spreadsheet export or names pasted into chat. Name plus website is best, because names alone are ambiguous.
3. **A column spec**, decided before the run. Five to eight columns is plenty for a first pass.
4. **Optionally, a destination app** such as Google Sheets, Airtable or HubSpot, connected from Settings, Connections or from the connect card the agent shows in chat.

Research covers what companies publish. For data behind a login, export it and upload the file. Some sites prohibit automated access; "not found" is the right answer there.

## Seven steps from list to spreadsheet

### 1. Give the agent the list

<Prompt>

I uploaded prospects.csv. It has company names in column A and websites in column B. Read it, tell me how many rows it has, and flag any row with a missing or obviously wrong website. Do not research anything yet.

</Prompt>

Construct opens CSV and Excel files in its sandbox, which has Python with pandas and openpyxl installed, so the export does not need cleaning first.

### 2. Define the columns and the evidence rule

<Prompt>

For each company, fill these columns: company, website, one-line description of what they sell, headquarters country, pricing model (free, freemium, per seat, usage based, contact sales, or not published), lowest paid price in USD, the billing period that price is for, the price when billed monthly, whether they offer a free plan, and one news item from the last 12 months if one exists.

Rules: use only pages you actually fetched, and put the URL you read in a source column next to each fact. If a pricing page has a monthly and yearly toggle, open it in the browser and switch to monthly before recording the monthly price. If you cannot find something, write "not found". If two sources disagree, write "conflicting" and put both URLs in a notes column. Record the date you checked each company.

</Prompt>

"Not found" and "conflicting" are what make the sheet trustworthy: a blank you can see costs less than a plausible guess you cannot.

### 3. Pilot three companies

<Prompt>

Do the first three companies only. Save the result to Files as research/prospects-pilot.csv and tell me anything you were unsure about.

</Prompt>

Open the CSV in Files, where it displays as a table, and click three or four source links. If "pricing model" came back in five different phrasings, tighten the allowed values in step 2 and run the pilot again.

### 4. Run the rest in batches

<Prompt>

The pilot is good. Research the remaining companies with the same columns and rules. Work in batches of 10, append each batch to research/prospects.csv as you finish it, and tell me when each batch is saved.

</Prompt>

Because each batch is written as it finishes, a run that stops at its step limit keeps every row already saved, and the next run picks up from the last company. For long lists, ask Construct to split the work across temporary helper agents: Lite runs 2 at once, Starter 4 and Pro 8. Helpers cannot connect apps or ask you questions, which does not matter for public research.

<Prompt>

Split the remaining companies into four groups and research each group with a helper agent using the same rules. Merge the results into research/prospects.csv sorted by company name, and list any company a helper could not finish.

</Prompt>

Descriptions and prices often contain commas, which break a CSV that is not quoted properly. When an agent writes a CSV, Construct checks it against the CSV standard (RFC 4180) and, if a line is wrong, the agent is told which line and why, for example that it "has 11 fields where the first line has 10", so it can rewrite the file before you open it.

### 5. Ask for a gap report

<Prompt>

Read research/prospects.csv. Count the "not found" and "conflicting" cells per column, list every row where a fact has no source URL, and save that as research/prospects-gaps.md.

</Prompt>

A fact without a URL is a bug in the run, not a judgment call. Send those rows back for another pass.

### 6. Send the rows where they need to go

The CSV in Files is the source of truth. Download it, ask for an Excel copy, or have the agent push rows into a connected app: Composio's toolkits, which Construct's app catalog draws on, include actions to add rows to a Google Sheet, create Airtable records and create HubSpot companies ([Google Sheets](https://docs.composio.dev/toolkits/googlesheets), [Airtable](https://docs.composio.dev/toolkits/airtable), [HubSpot](https://docs.composio.dev/toolkits/hubspot)).

<Prompt>

Create research/prospects.xlsx from prospects.csv with frozen headers, the source columns as clickable links, and "not found" cells shaded.

</Prompt>

If the rows are going into HubSpot, search before you create: HubSpot does not deduplicate companies created through its API by domain. Our [HubSpot lead sourcing guide](/blog/ai-lead-sourcing-hubspot/) has the prompt.

### 7. Save the format for next time

<Prompt>

Remember the column spec and evidence rules from this job as my "company research" format. Next time I give you a list, use that format unless I say otherwise.

</Prompt>

You can read, correct or delete what it stored in the Memories app ([AI agent memory](/blog/ai-agent-memory/)). Once the job has worked a few times it can become a scheduled refresh; Lite includes 3 scheduled tasks, Starter 10 and Pro 50 ([scheduling guide](/blog/ai-agent-scheduled-tasks/)).

## How to check the sheet for made-up facts

Check the sources, not the prose. Read every cell in the three-company pilot; after that, sample a few rows per batch, opening the link beside each cell to confirm the page says what the cell says. The gap report lists every fact without a source, so nothing unsourced slips through. When a cell looks wrong, Activity lists the pages the run fetched and the files it wrote ([what an activity log shows](/blog/ai-agent-activity-log/)). Keep writes to other systems for last: research is read-only until step 6.

## Troubleshooting

**The agent researched the wrong company.** Add websites to the input file. Names like "Atlas" or "Nova" match dozens of companies.

**Cells have answers but no sources.** Restate the rule from step 2, run the gap report, and send the unsourced rows back.

**The run stopped partway.** Check Files for the last saved batch, then ask the agent to continue from the next company.

**Prices look low.** It probably recorded the annual price. Check the billing period column and have the agent switch the page's toggle in the browser.
