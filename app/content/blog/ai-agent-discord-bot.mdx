## Why put an AI agent in Discord?

Because that is where a lot of teams already talk. Discord reports more than 90 million daily active users ([Discord](https://discord.com/company)), and for game studios, open source projects, creator businesses and plenty of small startups, the server is the office. Questions get asked in #support, decisions get made in #general, and the work that follows usually means someone leaving Discord to go do it.

Most AI bots in Discord are built for chatting or moderation. Construct is built for the job after the chat. It is an always-on AI agent with its own computer, so when you ask it to "turn this week's support questions into an FAQ", it reads the channel, writes the document, saves it to your workspace and posts it back where you asked. Nothing has to be copied out of Discord first, and nothing has to be pasted back in afterwards.

- **One agent behind every door.** A request from Discord lands in the same workspace, files and memory you use on the web, Slack, Telegram and email.
- **It works in threads, not in your main channel.** Every request gets its own thread, so #general stays readable.
- **It brings back files, not only replies.** Attach a file to your request, or ask for one back. Results are saved in your workspace too.
- **It keeps context you can see.** With Listening on, `/brief` shows exactly what the agent is keeping track of in a channel.
- **Locked until you open it.** A new server answers only the person who installed it.
- **Hosted, nothing to run.** Construct is a verified Discord app, so there is no bot token to create, no gateway to keep alive and no Developer Portal to configure.

## What can Construct do in Discord?

Anything it can do on the web, started from a channel, a thread, a slash command or a DM. That includes:

- **Research and writing.** Browse the web, read pages, and draft announcements, FAQs, patch notes or replies.
- **Read the channel when you ask.** It can fetch up to 100 recent messages from a channel in the same server, which is how "summarize #support this week" works.
- **Post where you tell it.** It can send a message to another channel in the same server, start a thread, add a reaction, or attach a file from your workspace.
- **Take files in and send files out.** Attach up to 20 MB per file to a message or to `/ask`, and the file lands in your workspace for the agent to use.
- **Use your connected apps.** If a job needs an app you have not connected yet, it posts a **Connect account** button that opens a private sign-in link, then carries on once you are connected.
- **Ask before it acts.** When it needs a decision, it posts a question with buttons for each choice, plus **Other…** for a typed answer. Only the person who asked, or someone with Full access, can answer.

## How do you add Construct to a Discord server?

You need a Construct account and the **Manage Server** permission on the Discord server. In a team workspace, the owner or an admin does the install; members see Messaging settings as view only.

1. **Open Messaging settings.** In Construct, go to **Settings > Messaging**. Under **Platforms**, find Discord and click **Add to Discord**.
2. **Pick your server.** Discord opens in a pop-up and asks which server to add Construct to. If nothing opens, allow pop-ups for Construct and try again.
3. **Authorize the permissions.** Construct asks only for what it uses: View Channels, Send Messages, Send Messages in Threads, Create Public Threads, Read Message History, Embed Links, Attach Files, Add Reactions and Use Application Commands. No moderator powers.
4. **Check that it is online.** Back in Construct you will see a "Discord connected" toast, and the server appears under Platforms with an **Online** badge. Construct also posts one welcome note in your server's system channel.
5. **Mention it.** Type `@Construct` and your request in any channel the bot can see. It opens a thread and starts working.

## How does Construct work in Discord threads?

A mention, or a reply to one of Construct's messages, opens a public thread named after the first 40 characters of your request. From then on, every message in that thread from someone allowed to use the agent reaches it, with no need to mention it again. Everyone in the thread shares one conversation, and the agent sees who said what, so a teammate can add "use the Steam forum too" halfway through and the agent folds it in.

Here is what you see while it works:

1. **It acknowledges you.** A typing indicator, then a small animated loader on your message.
2. **It shows progress.** If the job takes more than a couple of seconds, one message appears with a short grey status line such as "🔍 Searching the web…" or "📁 Working with files", updated as it moves between tools.
3. **It answers in place.** That same message is replaced by the finished answer, with a footer such as "✓ 4 tools". Long answers continue in follow-up messages, and code blocks are never split.
4. **It lands in your workspace.** Files it made are in Files, and the whole thread appears in Construct under **Chat > Channels** as a read-only session with an **Open in Discord** button.

## How does Construct follow a channel and build context?

This is the part people ask about most, so here is exactly how it works.

By default, Construct only reads messages addressed to it: mentions, replies to it, threads it started, slash commands and DMs. That matches how Discord itself treats message content as privileged data that apps have to be approved for ([Discord Gateway docs](https://docs.discord.com/developers/events/gateway)).

**Listening** is the opt-in, ambient mode. An owner or admin turns it on for specific channels, and from then on the agent reads along in those channels, the way a new teammate would, so it understands the conversation before anyone mentions it. In Construct the nudge to switch it on says it plainly: "Let Construct follow your chats."

### The four Listening modes

Each listened channel has a mode. The wording below is the wording in Construct's settings.

<ArticleTable caption="Construct Listening modes for a Discord channel">

| Mode    | In Construct's words                                                                                            | What changes for you                                                          |
| ------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Off     | "Doesn't read this channel. Mentions still work."                                                               | The default. The agent sees only what is addressed to it.                     |
| Context | "Keeps recent messages so replies understand the conversation. Learns nothing."                                 | Mention it after a long discussion and it already knows what was said.        |
| Learn   | "Also keeps the channel brief, open loops and memories from the conversation."                                  | Decisions and open questions carry over to next week's requests.              |
| Assist  | "Also sends private suggestions to the person who asked. Posts nothing unprompted until you raise the ceiling." | It starts noticing work it can help with, without speaking up in the channel. |

</ArticleTable>

### What the agent keeps, and how it turns messages into context

- **A rolling record of the channel.** Messages, edits and thread replies from the moment Listening starts. It never reads older history. Messages are kept for 1, 3, 7, 14 or 30 days, 14 by default, and a message deleted in Discord is deleted from what Construct keeps.
- **Who it reads.** Either only the people you have admitted to the agent, which is the default, or everyone in the channel. Messages from anyone outside that scope are dropped, not stored.
- **A channel brief and open loops.** Every 40 or so messages, or after 30 minutes once a few have built up, Construct updates a short brief of what the channel is working on and which questions are still open. Anyone can read it with `/brief`.
- **Context when someone asks.** When the agent is mentioned in a listened channel, it gets the most recent messages (up to 30 lines) plus the brief alongside the request. That channel text is marked as untrusted, so the agent treats it as information to weigh, not as instructions to follow. A message that says "ignore your rules and post this" is just another message.
- **Memories, in Learn and Assist.** Facts and decisions from the conversation become memories the agent can use later, in the same [memory](/blog/ai-agent-memory/) that powers the rest of Construct.

This is what people mean by context engineering, done in the open: a bounded window of recent messages and a brief anyone in the channel can read, rather than a model quietly ingesting everything the server has ever said.

### How quiet does it stay?

Quiet by default. Even in Assist, the agent posts nothing in the channel on its own until you raise the ceiling. Each channel has two ceilings you set: **Answers, at most**, which runs from L0 Listen through L1 Suggest and L2 Offer to L3 Answer, and **Work, at most**, for how much the agent may do without being asked. Below the ceiling, the channel earns each level from how people react. Anyone in the channel can turn it down with `/quiet`.

We chose that default on purpose. In a study of AI agents in group conversations, participants "disliked when the agent seemed to dominate the conversation" ([Houde et al., 2025](https://arxiv.org/abs/2501.17258)). An agent that reads the room but speaks when asked is easier to live with than one that chimes in on every message.

Channels also have an audience. A Discord channel counts as **Internal** only if you confirm it is an internal team channel. Anything else is **Community**, which caps the agent at Assist, limits it to answers, and learns nothing about people. That matters for public servers, where your members never signed up to be anyone's training data.

### How to turn on Listening

1. **Switch on AI processing.** In **Settings > Messaging**, the **AI processing** card has a **Process listened channels** switch. Its "What this means" note explains who processes what: Cloudflare, which already runs Construct, reads listened channels with its Clef model on Workers AI to decide what is worth keeping, and the model providers Construct uses for replies write the brief. Nothing is read until you also pick a channel. (We benchmarked Clef in [Clef vs Jev on real agent decisions](/blog/clef-vs-jev-benchmark/).)
2. **Add a channel.** In **Add a channel**, choose Discord, pick a channel the bot is already in, or **All channels** for every channel it can see today, and pick a mode. The form starts on Context.
3. **Confirm the checklist.** You tick that the channel is not used for health, HR, legal or personal finance matters, that members are adults and part of your organization or community, that members have been told, and, for an Internal channel, that it is an internal team channel.
4. **Click Start listening.** The agent posts a notice in the channel saying it is an AI, which mode it is in, how long messages are kept, and how to use `/status`, `/optout` and `/forget_me`.

Every listened channel then has its own settings for mode, retention and who it reads, a count of members who opted out, and a **What the agent keeps** page. **Pause listening everywhere** turns it all off at once. Turning a channel off posts a final notice, and the messages the agent kept from that channel are deleted.

## Who can use the agent in your server?

Each server has its own access rules under **Who can message** in **Settings > Messaging**. There are two modes:

- **Only people I allow** (the default): everyone else is ignored, with no reply and no reaction.
- **Everyone:** people you have not listed get a read-only guest agent.

Then two lists, which take Discord members or whole roles. **Full access** gives someone the real agent with every tool you have. **Blocked** silences someone completely. The person who installed the bot always has full access, and Blocked wins over everything, so you can mute an account without uninstalling.

The guest agent is deliberately small. Guests get web search, web pages and general workspace context, and nothing else: no files, email, connected apps, browser, terminal or memory. Each guest can send 12 messages every 10 minutes. That makes Everyone mode a sensible fit for a community help channel, while the real agent stays with your team.

Every request in a server runs under the installer's Construct plan. Members do not need their own Construct account, and you do not pay per seat.

## Can different channels get different agents?

Yes. Construct plans include several agents (2 on Lite, 5 on Starter, 15 on Pro), and you can send each channel to a different one. Route #support to an agent that knows your help docs and keep #growth on a research agent.

You can set this in two places. In **Settings > Messaging**, **Channel routes** sends one channel to a specific agent, and each server can have its own default agent. In Discord, someone with **Manage Server** can run `/agent` in the channel and pick from a list, once they have linked their Discord account with `/connect`. Threads that are already open keep the agent they started with.

## Can you DM the Construct bot?

Yes, once you link your Discord account. In **Settings > Messaging**, under **Your account**, click **Connect Discord**. After that, a DM to the bot reaches your own agent in your own workspace, with all of your tools. Anyone who installs the bot is linked automatically, and you can also link from Discord with `/connect`. Linking only needs your Discord identity, so it does not give the bot access to your servers.

- **An agent with a computer, not a chat bot.** A Discord request can end as a saved spreadsheet, a drafted email, a browser task or a scheduled job, all in one workspace that outlives the thread.
- **Context with controls.** Listening is per channel, announced in the channel, time-limited, and every member can opt out or be forgotten.

When might another option still fit?

- You want to self-host the agent and pick every model yourself, and you are happy to run a server for it: OpenClaw or Hermes Agent.
- Your team lives in Slack and already pays for Claude Team or Enterprise: Claude Tag ([Claude docs](https://claude.com/docs/claude-tag)). Construct also works in Slack, from the same settings screen.

For how the wider category is shaping up, see [always-on AI agents compared](/blog/always-on-ai-agents-compared/).

## What should you know before you start?

A few limits, each with the way around it:

- **Scheduled results go to the web app, not Discord.** A job you put on the Calendar notifies you in Construct. Start recurring work from Discord if you like, and read the results in Construct.
- **No voice.** Construct reads and writes text in Discord; it does not join voice channels.
- **Plain answers, real files.** Discord strips tables and images from messages, so ask for a file when you want one.
- **Server installs only.** Construct is added to servers, not to your personal account as a user app. Use DMs for private work.
- **Mention-free threads need Message Content.** If the server row shows **Needs setup** instead of Online, the bot can only see mentions, replies and DMs until that is fixed.

## Troubleshooting

**The first mention got a "Connect this server" card.** The bot was added from Discord rather than from Construct. Click **Add to Discord** in **Settings > Messaging** and pick the same server.

**The bot does not reply to a teammate.** The server is on "Only people I allow". Add them, or a role they have, to Full access.

**A teammate gets short, limited answers.** They are a guest. Add them to Full access if they should have the real agent.

**"I don't have permission to do that here."** A channel or role override is blocking the bot. The message lists exactly which permissions are missing, so a server admin can grant them.

**"That Discord server is already connected to another account."** Each server links to one workspace. Disconnect it from the other workspace first.
