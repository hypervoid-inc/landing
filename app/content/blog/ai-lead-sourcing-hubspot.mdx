AI lead generation into HubSpot works when the agent searches HubSpot before it creates anything. HubSpot deduplicates contacts by email, but it says "companies created through API will not be deduplicated by the Company domain name property. This includes installed third-party sync apps" ([HubSpot Knowledge Base](https://knowledge.hubspot.com/records/deduplication-of-records), updated October 2, 2026). Any agent writing through the API, Construct included, will create the same company twice unless it checks the domain first.

This guide sets up a weekday job in Construct that reads your ideal customer profile from a file, researches matching companies on the public web, searches HubSpot by domain and email, creates only what is new with a note citing the source, and posts a summary to your Slack sales channel.

## What the agent can do in HubSpot

Construct connects to HubSpot through Composio's HubSpot toolkit, which lists close to 300 actions ([Composio](https://docs.composio.dev/toolkits/hubspot), checked 2026-10-26). This job needs six of them:

<ArticleTable caption="HubSpot actions this job uses, from Composio's HubSpot toolkit (checked 2026-10-26)">

| Step                     | Composio action                                                 | What it does here                       |
| ------------------------ | --------------------------------------------------------------- | --------------------------------------- |
| Find an existing company | Search companies (`HUBSPOT_SEARCH_COMPANIES`)                   | Look up the domain before creating      |
| Find an existing contact | Search contacts (`HUBSPOT_SEARCH_CONTACTS`)                     | Look up the email before creating       |
| Add a company            | Create company (`HUBSPOT_CREATE_COMPANY`)                       | Name, domain, city                      |
| Add a contact            | Create contact (`HUBSPOT_CREATE_CONTACT`)                       | Only when a business email is published |
| Link them                | Associate (`HUBSPOT_BATCH_CREATE_CONTACT_COMPANY_ASSOCIATIONS`) | Contact to company                      |
| Explain the lead         | Create note (`HUBSPOT_CREATE_NOTE`)                             | The signal and its source link          |

</ArticleTable>

The same toolkit also has update, merge, archive and GDPR-delete actions. In Construct, per-agent **App access** is all or nothing for an app: an agent allowed to use HubSpot can call any action the connection offers. Two things narrow that. Give this job its own agent and turn HubSpot off for every other agent. And once the job is stable, save it as a workflow: a workflow's agent step can carry a list of allowed app actions (up to 32), so ask Construct to limit the HubSpot step to the six above. Our post on [what your AI agent can delete](/blog/what-can-your-ai-agent-delete/) covers the wider question.

## What you need

1. **A Construct plan sized for the batch.** Each round of tool calls, such as searches, page fetches and HubSpot calls, is a step. Lite allows 50 steps per task, Starter 150 and Pro 1,000; Lite includes 3 scheduled tasks and Starter 10 ([pricing](/pricing/)). On Lite, start with about three companies a day; on Starter, ten.
2. **HubSpot connected** from **Settings**, **Connections** (the **Open App Store** button) by someone allowed to install apps. In a team workspace every agent's HubSpot calls act as the person who connected it, so connect a HubSpot user whose permissions fit the job.
3. **Construct added to Slack** and the sales channel's email address, which needs a paid Slack plan. The [Slack briefing guide](/blog/ai-agent-slack-briefing/) covers both, and why a scheduled run reaches Slack by email.
4. **A written ideal customer profile**: industry, size, location, and the signal that makes a company worth a call this week.

## Set it up

### 1. Write the profile into a file

<Prompt>

Save this as Files/leads/profile.md. Target: independent physiotherapy clinics in the UK with 3 to 20 practitioners. Good signal: hiring a clinic manager or opening a second location in the last 60 days. Exclude: hospital groups, franchises, and anyone already in HubSpot. For each lead I need the company name, website domain, city, the signal with a source link, and a named owner or manager only if their name and business email are published on the company's own site.

</Prompt>

When the profile changes, you edit one file and the next run reads it.

### 2. Run the research once, without touching HubSpot

<Prompt>

Using Files/leads/profile.md, find 10 companies that match. Use public web sources only and record the URL where you found each signal. Do not guess email addresses; if a business email is not published on the company's own site, leave it blank. Save the results to Files/leads/ as a CSV named with today's date, with these columns: company, domain, city, signal, signal_url, contact_name, contact_email, hubspot_company_id, status. Do not create anything in HubSpot.

</Prompt>

Open the CSV and click every signal_url. This is where you learn whether "opening a second location" meant what you meant. Fix the profile and run it again until a whole batch holds up.

### 3. Add the leads to HubSpot, searching first

<Prompt>

For each company in today's CSV: normalise the domain (no protocol, no "www.", no path), then search HubSpot companies by domain. If one exists, set status to "existing" and its ID in hubspot_company_id, and do nothing else. Otherwise create the company with name, domain and city, and add a note on it with the signal and signal_url. For each contact email, search HubSpot contacts by email; if none exists, create the contact, set lifecycle stage to lead, and associate it with the company. Never update, merge, archive or delete an existing record. Set status to "created" and save the CSV.

</Prompt>

Open two created companies in HubSpot and check the domain, the note and the contact association before you schedule anything.

### 4. Send the summary to Slack

<Prompt>

Email a summary of today's new leads from your own address to sales-abc123@yourteam.slack.com with the subject "New leads" and today's date. One line per created company: name, city, signal, and the HubSpot link. End with how many were already in HubSpot. Under 150 words.

</Prompt>

Use the address Slack gave you, and check the post arrives.

### 5. Put it on the Calendar

<Prompt>

Every weekday at 6:30am in my time zone, run the lead job: steps 2 to 4 exactly as today, using Files/leads/profile.md and 10 companies, searching HubSpot before creating anything, never changing existing records, and emailing the summary to the Slack channel address. Skip any company listed in an earlier CSV in Files/leads/. If today's CSV already exists, stop.

</Prompt>

Open the event and set **Delivery behavior**, **If delivery is late** to **Run once**. The "already exists" line keeps a retried run from writing twice. Calendar runs happen in the cloud with your laptop closed ([scheduling guide](/blog/ai-agent-scheduled-tasks/)).

When someone in the channel wants detail, they can ask in the thread: "@Construct what did the second clinic's hiring post say?" The agent reads that day's CSV and its sources.

## How the HubSpot side behaves

**Contacts.** HubSpot's developer guide says "email address is the primary unique identifier to avoid duplicate contacts in HubSpot" ([HubSpot](https://developers.hubspot.com/docs/api-reference/latest/crm/objects/contacts/guide)). The API also has a batch upsert keyed on email, but "partial upserts are not supported when using email as the idProperty," which is one reason this job searches and creates instead.

**Companies.** The companies guide recommends you "always include domain, because domain names are the primary unique identifier to avoid duplicate companies" ([HubSpot](https://developers.hubspot.com/docs/api-reference/latest/crm/objects/companies/guide)), yet API-created companies are not deduplicated on it. The search before create is the only protection.

**Search limits.** CRM search is "rate limited to five requests per second per account," returns at most 200 records per page and 10,000 per query ([HubSpot](https://developers.hubspot.com/docs/api-reference/latest/crm/search-the-crm)). Ten companies and a few contacts a day are far inside that.

## Contacting UK and EU leads

Finding a lead is not permission to email them. In the UK, PECR's email marketing rule "does not apply to corporate subscribers," but "sole traders and other types of partnerships are classed as 'individual subscribers'," and UK GDPR applies to business contacts' personal data used for marketing: you "must tell them about this and have a lawful basis" ([ICO](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/business-to-business-marketing/), checked 2026-10-26). Many independent clinics are sole traders or partnerships, so check each lead's legal form before it goes into a sequence. The prompts above already store only emails a business publishes on its own site.

## HubSpot's own Prospecting Agent

HubSpot's Prospecting Agent researches accounts and drafts outreach inside HubSpot and charges "$1/per lead" when it recommends outreach ([HubSpot](https://www.hubspot.com/products/sales/ai-prospecting-agent)), paid in HubSpot Credits "at a cost of 100 credits per recommended lead" ([HubSpot, updated April 13, 2026](https://www.hubspot.com/company-news/hubspots-customer-agent-and-prospecting-agent-now-you-pay-when-the-task-is-complete)). The product page lists Starter, Professional and Enterprise; the April announcement says Pro and Enterprise, with a 28-day free trial. Checked 2026-10-26.

If your team already works leads in HubSpot sequences, it is the simpler choice: no connection to manage and no Slack workaround. Construct fits when the profile is your own and the research has to cite the page each signal came from, at a flat plan price.

## Troubleshooting

**Duplicate companies.** Check the scheduled prompt still says to search by domain first, and that domains are normalised. Merge the pair in HubSpot.

**The same leads every day.** The run is not reading earlier CSVs; keep the "skip any company listed in an earlier CSV" line.

**The run stopped partway.** It used every step it was allowed on that run. Say continue in its chat to pick up where it stopped, and lower the batch or move up a plan; rows already saved to the CSV stay.

**No Slack post.** Check the channel address, your Slack plan, and whether your Slack admin allows channel emails, then press **Run now** on the event.
