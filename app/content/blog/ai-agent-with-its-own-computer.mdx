**An AI agent with its own computer is an agent that gets a persistent machine in the cloud: a browser, a terminal, a file system, connected apps, and often its own email address.** Because the work runs on that machine instead of your laptop, it keeps going when you close the lid, and a job can run on a schedule at 3am without anyone watching.

In the last three months almost every major AI platform shipped one. Prices start at $9 a month for [Construct](/pricing/) and run to $200 a month for Perplexity Computer or an always-on machine from Simular, with most of the big-platform versions bundled into $20 to $125 subscriptions you may already pay for.

## What is an AI agent with its own computer, exactly?

A chat assistant answers inside a conversation. An agent with its own computer is given somewhere to work: it can open a website, log in, download a file, run a script against it, save the result, and pick the job up tomorrow from what it left behind.

Satya Nadella put the idea in one line on April 22, 2026: "Every agent will need its own computer." He was announcing Microsoft's hosted agents in Foundry, where, in his words, "every agent gets its own dedicated enterprise-grade sandbox, with durable state, built-in identity and governance" ([Nadella on X](https://x.com/satyanadella/status/2047033636923568440); [Microsoft Foundry announcement](https://devblogs.microsoft.com/foundry/introducing-the-new-hosted-agents-in-foundry-agent-service-secure-scalable-compute-built-for-agents/)).

You will see the same thing sold under several names: always-on agent, cloud agent, background agent, AI employee, AI coworker, computer-use agent. The label matters less than four properties:

1. **A machine it controls.** A real browser and usually a terminal, not just API calls.
2. **State that persists.** Files, logins, and memory survive between tasks.
3. **Work that runs without you.** Schedules, triggers, or long jobs that do not need an open tab.
4. **An identity to act with.** Your connected accounts, its own inbox, or both.

A product with only the first is a computer-use feature inside a chat. Our guide to [what an AI employee is](/blog/what-is-an-ai-employee/) covers the wider category these products sit in.

## Why did every platform ship one in 2026?

Because the model stopped being the bottleneck. Agents could already click and type in 2025. What they lacked was somewhere to stay. A browser session that dies when your laptop sleeps cannot run a weekly report, and an agent that loses its files between tasks starts every job from zero.

## How does an AI agent with its own computer work?

Strip away the branding and most of these products have the same five parts.

**1. A sandbox or virtual machine.** The agent's actions run in an isolated environment on the vendor's servers. Some vendors keep a whole machine switched on for you (Simular's Premium plan sells "an always-on Windows or Mac machine," [Simular pricing](https://www.simular.ai/pricing)). Others keep your files and state permanently but start the compute only when there is work. Microsoft's hosted agents keep the file system across idle periods and scale the compute down in between ([Microsoft](https://devblogs.microsoft.com/foundry/introducing-the-new-hosted-agents-in-foundry-agent-service-secure-scalable-compute-built-for-agents/)). Marketing rarely says which model a product uses, and it affects both price and capability.

**2. A browser the agent drives.** This is what lets it work in tools that have no integration: a supplier portal, a government form, a dashboard behind a login. Several products let you watch. OpenAI says you can open your dot's cloud computer "at any time to see what it is doing" ([SiliconANGLE](https://siliconangle.com/2026/09/29/openai-launches-dots-always-on-ai-agents-in-chatgpt-with-their-own-cloud-computers/)).

**3. Credentials and app connections.** The agent acts through connected accounts (Gmail, Slack, a CRM), through logins saved in its browser, or through an identity of its own, such as a dedicated email address. Dots connect to "more than 4,000 apps through plugins" ([The Next Web](https://thenextweb.com/news/openai-dots-always-on-ai-agents-cloud-computers-devday)). This is the part that makes the agent useful and the part that makes it dangerous.

**4. Schedules and triggers.** Work starts from a calendar entry, an incoming email, or a message, not only from you typing. Claude's guide notes that "scheduled tasks run in the cloud, so they don't need your computer to be awake" ([Anthropic](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)).

**5. Memory and files.** What the agent learned and produced is still there for the next run. That is what turns a clever one-off into something you can hand a weekly job.

### An illustrative example

Illustrative, not a customer case study. A two-person agency wants a Monday briefing on five competitors' pricing pages. On Sunday night the schedule fires. The agent opens each page in its browser, saves a copy, compares it with last week's saved copy in its files, writes a one-page summary, and emails it to the founders. Nobody's laptop is on. On Monday the summary, the five snapshots, and a record of what the agent did are sitting in the workspace, and next week's run starts from this week's files.

None of those steps is hard. Each one just needs a place to run and a place to keep things.

## Why does it matter?

Three kinds of work become possible that a chat window cannot hold.

**Long jobs.** A task that takes 40 minutes of browsing and file work does not fit in a request that times out when you switch tabs. On its own machine, the agent can grind through it.

**Recurring work.** Monthly reports, daily inbox triage, weekly checks. The value of an agent grows when you stop having to start it.

**Work you can inspect.** Output lands as files, sent messages, and records you can open afterwards, not as a paragraph in a thread you will never scroll back to. When something goes wrong, there is something to look at.

The catch with long and recurring jobs is reliability. Small per-step error rates compound: a 95% reliable agent finishes a 48-step job about 8.5% of the time, which is why [agents keep failing halfway through long tasks](/blog/agent-task-half-life/). A persistent computer does not fix that by itself. It helps only if finished work is saved as it goes, so a run that dies at step 30 leaves steps 1 to 29 behind for the next attempt.

## How do you evaluate an AI agent with its own computer?

Most launch pages read the same. These questions separate the products quickly.

1. **Is the computer always on, or only the state?** An always-on machine can host a long-running process, like a server or a bot that watches a feed. A workspace with on-demand compute is cheaper and fine for jobs that start, work, and finish. Know which one you need.
2. **Does it keep working with every device off?** Test it: schedule a job, close everything, and check the result in the morning. Some features still need a desktop app open to reach local files.
3. **Whose identity does it act with?** Your own Gmail, a scoped connection, or an address of its own? A separate identity limits what a mistake can reach.
4. **What needs your approval?** Look for documented rules. Google says Spark asks "before performing high-stakes actions like spending money or sending emails," and Meta says Muse for Small Business "will not publish content, send messages or spend money unless the user authorizes it."
5. **Can you see what it did?** Watching a live browser is good. Files, sent messages, and a step-by-step record you can read afterwards are better.
6. **What happens when a run fails halfway?** Ask whether finished work is saved as it goes, or whether a failure means starting over.
7. **How is it metered, and can you cap it?** Credits, tokens, weekly limits, and seats behave differently in a heavy month. Find the spending cap before you schedule anything.
8. **Are agents isolated from each other?** If several agents share one machine and one set of logins, they are not a security boundary.
9. **Where can you reach it?** Slack, email, WhatsApp, or only the vendor's app. The best agent is the one your team will actually message.
10. **What happens to its files if you cancel?** Find out before the work that matters lives there.

## What are the risks?

Giving software a computer and your logins moves risk from "it said something wrong" to "it did something wrong." Three risks matter most.

**Credential access.** An agent that can send email as you can send the wrong email as you. In February 2026, Summer Yue, Meta's AI alignment director, described an OpenClaw agent that began deleting emails in her real inbox after losing her instruction to wait for approval. She said, "I couldn't stop it from my phone," and "I had to RUN to my Mac mini like I was defusing a bomb" ([Business Insider via AOL](https://www.aol.com/articles/meta-ai-alignment-director-shares-195622792.html)). That agent ran on her own machine, not a vendor's cloud, but the lesson carries over: scope what the agent can reach and test on data you can afford to lose.

**Prompt injection.** An agent that reads the web and your inbox will read instructions written by strangers. Simon Willison calls the dangerous combination the "lethal trifecta": "access to your private data," "exposure to untrusted content," and "the ability to externally communicate" ([Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)). An agent with its own computer usually has all three by design. Approval rules on sending and spending are the practical defense.

**Runaway cost.** An agent that works while you sleep can also spend while you sleep. In late September 2026, a developer posted to Hacker News that an OpenAI Codex task had spawned 826 child agents and run up roughly $78,000 in charges ([Hacker News](https://news.ycombinator.com/item?id=49861047)). Treat that as a claim, not a confirmed incident: the post was flagged, commenters questioned it, and we found no public response from OpenAI. The failure mode it describes is real either way, which is why the evaluation checklist asks about spending caps.

There is a quieter risk too: work nobody checks. Nine reports produced overnight have not saved you time until someone confirms they are right.

## Where does Construct fit?

We build Construct, so weigh this section accordingly. Construct is an AI employee for solo founders and small teams, and every agent works from a persistent cloud workspace: files, live browser runs, a sandbox terminal, a native agent email address, a calendar of scheduled jobs, and connected apps through a live integration catalog (Gmail, Notion, Linear, GitHub, HubSpot, Airtable, and more) plus custom MCP tools. You can reach it from the web, Slack, Telegram, Discord slash commands, or by emailing its inbox.

It is honest to say Construct's computer is mostly asleep. Our engineering write-up, [all our agents get computers, we pay for almost none](/blog/running-ai-agents-on-cloudflare-not-vms/), explains the design. The agent loop lives in a Cloudflare Durable Object that hibernates between events. When the agent needs Linux, a sandbox starts for that command and goes to sleep after about ten minutes idle. Workspace files live in object storage mounted into the sandbox, so they outlive the machine. Nobody pays for an idle box, which is how an account that is not working costs very little to run.

The tradeoffs are real and they come from that design:

- **No long-lived processes.** Terminal commands are capped at 300 seconds, and every command starts in a fresh shell. If you need something running continuously, like a game server, an always-on machine from Manus or Simular fits better.
- **Linear workflows.** Saved workflows run step by step today, with no branching, delays, or approval gates.
- **Useful records, not a forensic log.** Activity summaries and bounded tool records help you trace a run, but they are not a complete, immutable audit log.

Where it works well is the recurring, cross-app job. Finished work lands in the workspace as it is produced, so the next run picks up from what exists, and memory can be inspected, corrected, or forgotten. ## Give an agent its own computer for one job

Pick one job that repeats and does not need a human in the middle: a weekly report, a daily inbox sort, a monthly check. Run it on demand a few times, read what it produces, and only then put it on a schedule. Start with [Construct Lite at $9 a month](/pricing/) or the seven-day Pro trial, and judge it by the files it leaves behind.
