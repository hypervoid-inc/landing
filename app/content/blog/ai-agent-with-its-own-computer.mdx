## What is an AI agent with its own computer, exactly?

A chat assistant answers inside a conversation. An agent with its own computer is given somewhere to work: it can open a website, log in, download a file, run a script against it, save the result, and pick the job up tomorrow from what it left behind.

Satya Nadella put the idea in one line on April 22, 2026: "Every agent will need its own computer." He was announcing Microsoft's hosted agents in Foundry, where, in his words, "every agent gets its own dedicated enterprise-grade sandbox, with durable state, built-in identity and governance" ([Nadella on X](https://x.com/satyanadella/status/2047033636923568440); [Microsoft Foundry announcement](https://devblogs.microsoft.com/foundry/introducing-the-new-hosted-agents-in-foundry-agent-service-secure-scalable-compute-built-for-agents/)).

You will see the same thing sold under several names: always-on agent, cloud agent, background agent, AI employee, AI coworker, computer-use agent. The label matters less than four properties:

1. **A machine it controls.** A real browser and usually a terminal, not just API calls.
2. **State that persists.** Files, logins, and memory survive between tasks.
3. **Work that runs without you.** Schedules, triggers, or long jobs that do not need an open tab.
4. **An identity to act with.** Your connected accounts, its own inbox, or both.

A product with only the first is a computer-use feature inside a chat. Construct has all four. Our guide to [what an AI employee is](/blog/what-is-an-ai-employee/) covers the wider category these products sit in.

## How does an AI agent with its own computer work?

Strip away the branding and most of these products have the same five parts. Here is what each one looks like in Construct.

**1. A sandbox or virtual machine.** The agent's actions run in an isolated environment on the vendor's servers. Some vendors keep a whole machine switched on for you (Simular's $500 Sai Unlimited plan includes an "Always-on cloud computer (Windows or Linux)," [Sai pricing](https://sai.work/pricing)). Others keep your files and state permanently and start the compute only when there is work, as Microsoft's hosted agents do ([Microsoft](https://devblogs.microsoft.com/foundry/introducing-the-new-hosted-agents-in-foundry-agent-service-secure-scalable-compute-built-for-agents/)). Construct takes the second approach: workspace files are permanent, and a Linux sandbox starts when the agent needs one.

**2. A browser the agent drives.** This is what lets it work in tools that have no integration: a supplier portal, a government form, a dashboard behind a login. Construct runs live browser runs inside the agent's workspace, and what it collects lands in Files.

**3. Credentials and app connections.** The agent acts through connected accounts (Gmail, Slack, a CRM), through logins saved in its browser, or through an identity of its own. Construct connects apps from a live integration catalog, adds your own MCP tools, and gives every agent its own email address, so it can send as itself instead of as you. This is the part that makes an agent useful and the part that needs the most care.

**4. Schedules and triggers.** Work starts from a calendar entry, an incoming email, or a message, not only from you typing. In Construct, Calendar schedules run on the server with your laptop closed, and you can hand the agent work from the web, Slack, Telegram, Discord, or by emailing its inbox.

**5. Memory and files.** What the agent learned and produced is still there for the next run. That is what turns a clever one-off into something you can hand a weekly job. In Construct, you can open that memory, correct a fact, or tell the agent to forget it.

### An illustrative example

Illustrative, not a customer case study. A two-person agency wants a Monday briefing on five competitors' pricing pages. On Sunday night the Construct Calendar fires. The agent opens each page in its browser, saves a copy, compares it with last week's saved copy in Files, writes a one-page summary, and emails it to the founders from its own address. Nobody's laptop is on. On Monday the summary, the five snapshots, and an Activity record of what the agent did are sitting in the workspace, and next week's run starts from this week's files.

None of those steps is hard. Each one just needs a place to run and a place to keep things.

## Why does it matter?

Three kinds of work become possible that a chat window cannot hold.

**Long jobs.** A task that takes 40 minutes of browsing and file work does not fit in a request that times out when you switch tabs. On its own machine, the agent can grind through it.

**Recurring work.** Monthly reports, daily inbox triage, weekly checks. The value of an agent grows when you stop having to start it.

**Work you can inspect.** Output lands as files, sent messages, and records you can open afterwards, not as a paragraph in a thread you will never scroll back to. When something goes wrong, there is something to look at.

The catch with long and recurring jobs is reliability. Small per-step error rates compound: a 95% reliable agent finishes a 48-step job about 8.5% of the time, which is why [agents keep failing halfway through long tasks](/blog/agent-task-half-life/). A persistent computer does not fix that by itself. It helps only if finished work is saved as it goes, which is how Construct works: a run that stops at step 30 leaves steps 1 to 29 behind, and the next attempt picks up from there.

## How do you evaluate an AI agent with its own computer?

Most launch pages read the same. These questions separate the products quickly, and each one ends with how Construct answers it.

1. **Is the computer always on, or only the state?** An always-on machine can host a long-running process. A workspace with on-demand compute is cheaper and fits jobs that start, work, and finish. Construct keeps state permanently and starts compute when there is work.
2. **Does it keep working with every device off?** Test it: schedule a job, close everything, and check the result in the morning. Construct's Calendar schedules run on the server.
3. **Whose identity does it act with?** Your own Gmail, a scoped connection, or an address of its own? A separate identity limits what a mistake can reach. Every Construct agent has its own email address, and you connect your own accounts only where a job needs them.
4. **What needs your approval?** Look for documented rules. Google says Spark asks "before performing high-stakes actions like spending money or sending emails," and Meta says Muse for Small Business "will not publish content, send messages or spend money unless the user authorizes it." In Construct, the agent asks when unsure in chat, and for customer-facing work you ask for drafts and send them yourself.
5. **Can you see what it did?** Watching a live browser is good. Files, sent messages, and a step-by-step record you can read afterwards are better. Construct saves output to Files, and Activity records each action with a short reason for a limited window.
6. **What happens when a run fails halfway?** Ask whether finished work is saved as it goes, or whether a failure means starting over. In Construct, a run that stops at step 30 keeps steps 1 to 29.
7. **How is it metered, and can you cap it?** Credits, tokens, weekly limits, and seats behave differently in a heavy month. Find the spending cap before you schedule anything. Construct plans have a fixed monthly price with published plan limits and no per-message billing, and on Pro your own model keys bill you directly when used.
8. **Are agents isolated from each other?** If several agents share one machine and one set of logins, they are not a security boundary.
9. **Where can you reach it?** Slack, email, WhatsApp, or only the vendor's app. The best agent is the one your team will actually message. Construct answers on the web, Slack, Telegram, Discord, and its own email inbox.
10. **What happens to its files if you cancel?** Find out before the work that matters lives there.

## What are the risks?

Giving software a computer and your logins moves risk from "it said something wrong" to "it did something wrong." Three risks matter most.

**Credential access.** An agent that can send email as you can send the wrong email as you. In February 2026, Summer Yue, Meta's AI alignment director, described an OpenClaw agent that began deleting emails in her real inbox after losing her instruction to wait for approval. She said, "I couldn't stop it from my phone," and "I had to RUN to my Mac mini like I was defusing a bomb" ([Business Insider via AOL](https://www.aol.com/articles/meta-ai-alignment-director-shares-195622792.html)). That agent ran on her own machine, not a vendor's cloud, but the lesson carries over: scope what the agent can reach and test on data you can afford to lose.

**Prompt injection.** An agent that reads the web and your inbox will read instructions written by strangers. Simon Willison calls the dangerous combination the "lethal trifecta": "access to your private data," "exposure to untrusted content," and "the ability to externally communicate" ([Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)). An agent with its own computer usually has all three by design. Approval rules on sending and spending are the practical defense.

**Runaway cost.** An agent that works while you sleep can also spend while you sleep. In late September 2026, a developer posted to Hacker News that an OpenAI Codex task had spawned 826 child agents and run up roughly $78,000 in charges ([Hacker News](https://news.ycombinator.com/item?id=49861047)). Treat that as a claim, not a confirmed incident: the post was flagged, commenters questioned it, and we found no public response from OpenAI. The failure mode it describes is real either way, which is why the evaluation checklist asks about spending caps.

There is a quieter risk too: work nobody checks. Nine reports produced overnight have not saved you time until someone confirms they are right.

**How Construct handles these.** The agent works from its own email address, so a mistake lands in its mailbox instead of yours, and only mail from your own account address starts a run, so a stranger's email cannot hand it a job. Memory is open to inspection, so a wrong rule can be corrected rather than guessed at. Each plan has a fixed monthly price with published plan limits. And because every result is a file in the workspace, checking the overnight work means opening it, not scrolling a thread.
