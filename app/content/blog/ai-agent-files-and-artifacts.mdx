## Why do this in Construct?

- **Work is saved as it is produced.** A run that stops at step 30 keeps steps 1 to 29 in Files, and the next run picks up from what exists.

## Why does it matter where an agent's work goes?

Because a good answer that only exists in a chat thread is nearly as lost as no answer. Two weeks later nobody can find it, nobody else on the team has seen it, and next month's run cannot compare against it.

Finding work is already a large cost before AI enters the picture. In Microsoft's 2023 Work Trend Index survey of 31,000 workers, "62% of survey respondents say they struggle with too much time spent searching for information in their workday" ([Microsoft Work Trend Index, May 9, 2023](https://www.microsoft.com/en-us/worklab/work-trend-index/will-ai-fix-work)). An agent that produces more output in more threads makes that worse unless the output has a home.

A useful agent does three things with its work: saves it somewhere durable as it goes, names it so a person can find it, and reads it back next time. Construct does all three in the workspace's Files.

## Where do Construct's files live?

Every Construct workspace has a Files app, the same files the agent reads and writes.

- **Private.** Your own files. In a personal workspace this is everything; in a team workspace each member has a private area nobody else can browse.
- **Team.** In a team workspace, a shared area every member with file access can read, and members with write access can change.
- **Shared with you.** Individual files a teammate has shared with the whole team or with specific people. You can open them, not edit them in place.

The agent's terminal sees the same files: your private files at `/private` and the team area at `/workspace`. A script the agent runs writes straight into Files, so there is no export step between "the agent made it" and "you can open it."

Files can be previewed on the desktop without downloading: PDF, Word, PowerPoint, CSV, Markdown, HTML, JSON, images, audio and video, and zip archives. Text and code open in an editor. Storage counts against the workspace owner's plan.

## How does the agent create and protect files?

The agent has a files tool that can read, write, edit, list, search, and delete, and a few actions that matter for real deliverables:

- **Designed PDFs from Markdown.** The agent writes a report in Markdown and exports a PDF next to it, with a report or minimal style, page numbers, bookmarks from headings, and repeated table headers. Images in the Markdown appear as their description in the PDF, so keep charts as separate files.
- **Office formats.** For Word, Excel, and PowerPoint files, the agent writes them with Python in the terminal, which has the standard document libraries installed, and LibreOffice for conversions.
- **Imports.** The agent can download a file from an HTTPS link into Files (up to 25 MB), so a published dataset or a vendor's price sheet becomes a workspace file before anything else happens.
- **Attachments in chat and email.** It can attach up to eight workspace files to a chat reply, and up to eight to an email from its native inbox.
- **No silent overwrites.** The agent tracks which version of a file it last read. If you change the file after that, its next write is refused as a conflict instead of replacing your edit.

Incoming material lands in Files too. When an email or a Slack, Telegram, or Discord message with attachments starts a task, the attachments are saved under an inbox folder in the workspace, so the agent works from a file rather than a message.

## What about apps?

Some outputs are better as a small tool than a document: a review queue, an intake form, a dashboard over last month's reports. Construct can build a private workspace app for that. Its source lives in `Apps/<app-id>/` in Files, its saved records in `AppData/<app-id>/`, and a successful build opens on your desktop. If a later edit fails to build, the last working version keeps running. ## Files, memory, or an app?

Each kind of output has a natural home in Construct, and putting it in the right one is how work stays findable.

<ArticleTable caption="Where each kind of agent output belongs in Construct">

| Output | Best home | Why |
| --- | --- | --- |
| A report, spreadsheet, deck, or PDF | Files | You open it, share it, and compare it next time |
| A stable fact or preference | Memory | The agent recalls it before the next task, and you can correct it |
| A queue or tracker people update | Workspace app | People need a screen, not a document |
| A repeated procedure | Workflow | The steps run the same way each time |
| A live number, such as today's revenue | Neither, fetch it at run time | A saved figure is right only until it changes |

</ArticleTable>

## Before you start

Set up Files with these in mind and the first month goes smoothly:

- **Keep final copies where your team already works.** Files is not a desktop sync drive. If your team lives in Google Drive or Dropbox, connect it from the integration catalog and ask the agent to place final copies there, while working files stay in Construct.
- **Use dated filenames.** Files has no trash or version history, so an overwrite replaces the previous contents and a deleted file is gone. Dated filenames give you a history for free, and a standing instruction such as "never delete files" keeps it safe. {/* TODO: confirm Files has no trash or version history today */}
- **Edit Office files through the agent.** Word, Excel, and PowerPoint files preview in Files; to change one, ask the agent for a new version or download it.
- **Size the plan to the archive.** 100 MB on Lite fills quickly with PDFs and images. Starter's 1 GB or Pro's 3 GB suit a team archiving reports; see [pricing](/pricing/). Files are deleted when an account closes, so export what you need first.

## A concrete job: the weekly client report that builds on itself

This example is illustrative, not a customer case. A three-person marketing agency sends each client a short weekly report.

**The request, once, in chat:**

> Every Monday at 8am, for each client folder in Team/clients, read last week's report in reports/, pull this week's numbers from the connected analytics app, and write reports/YYYY-MM-DD-weekly.md comparing the two. Export it to PDF in the same folder. Save the raw numbers to data/YYYY-MM-DD.csv. Then post a one-line summary per client to me in chat. Do not email clients.

**What is left behind after the first run, for each client:**

- `Team/clients/acme/reports/2027-01-04-weekly.md` and the matching PDF
- `Team/clients/acme/data/2027-01-04.csv`
- An Activity row for each step, and the chat where the run happened

**What the second run does differently.** It starts by reading the previous week's Markdown and CSV, so the comparison is against what was actually sent, not against the agent's recollection. If the second run fails halfway, the clients it finished keep their files, and the next run picks up from there.

**Where a person stays in the loop.** An account manager opens each PDF, edits anything wrong, and sends it. Because the agent refuses to overwrite a file someone changed after it read it, those edits are safe from the next scheduled write. After a month, the folder is a clean history of every report, which is exactly what a client asks for at renewal.

## How to evaluate where any agent product puts its work

If you are comparing agents, ask each one these questions.

1. **Is there a file system you can browse,** or only attachments in a chat?
2. **Does the next run read the last run's output** automatically, or do you paste it back in?
3. **Can a teammate open the file** without your login?
4. **What happens if you edit a file the agent is about to rewrite?**
5. **Which formats can it produce properly:** PDF, Excel, Word, slides, charts?
6. **How much storage, and whose plan pays for it?**
7. **What happens to work from a run that fails halfway?**

Construct's answers: yes; yes; yes, in a team workspace; the write is refused; all five; 100 MB to 3 GB on the owner's plan; and the finished steps stay in Files.
