Everything a Construct agent makes, from a weekly report to a chart or a cleaned spreadsheet, is saved as a file in the workspace's Files, the same files the agent's terminal reads and writes. A team finds that work in a shared Team area or in dated folders, shares single files with specific people, and traces each file back to the chat that produced it through Activity. Two things to know before you rely on it: Files has no trash and no version history today, so a delete or an overwrite is final, and storage comes from the workspace owner's plan (100 MB on Lite, 1 GB on Starter, 3 GB on Pro).

Agents that answer only in a chat thread leave nothing a teammate can open next week and nothing the next run can compare against. This guide lists every place Construct puts an agent's output, how long each one lasts, and how to set up a folder that stays useful after months of runs.

## Everything a run can leave behind

A single run can leave output in several places. This table is all of them, as the product works today.

<ArticleTable caption="Where a Construct agent's output lands, and how long it lasts">

| Output                                            | Where it lives                                     | How long it lasts                      |
| ------------------------------------------------- | -------------------------------------------------- | -------------------------------------- |
| Reports, CSVs, charts, Word, Excel and PowerPoint | The folder you name in My files or Team            | Until someone deletes it               |
| PDFs exported from Markdown                       | Next to the Markdown file                          | Until someone deletes it               |
| Files downloaded from a link (up to 25 MB)        | `downloads/` unless you name a folder              | Until someone deletes it               |
| Workspace apps                                    | Source in `Apps/<id>/`, records in `AppData/<id>/` | The last 10 successful builds are kept |
| Terminal commands and their full output           | The Terminal app                                   | Until you choose Clear                 |
| Browser runs                                      | The Browser app: steps, screenshots, result        | Shown after the run ends               |
| What the agent did, step by step                  | Activity                                           | 30 days, or 10 MB per person           |

</ArticleTable>

The agent can also attach up to eight workspace files to a chat reply or to an email it sends from its own inbox. Those attachments are copies of files that stay in Files, so the folder remains the record.

## The three areas of Files

The Files app has three areas, and the agent works in the same ones:

- My files is private to you and the agents you work with. In the terminal it is `/private`.
- Team is shared with everyone in the workspace. In the terminal it is `/workspace`, and it is the only area mounted in the terminal when an agent works in a group chat, so commands run there cannot reach anyone's private files.
- Shared lists single files teammates shared with you. It is read-only.

Because the terminal and Files are the same storage, a script the agent runs writes straight into a folder you can open, and a file you drop into Files is there for the agent's next command. Moving a finished report from My files to Team is one action, **Move to Team**, in the file's menu.

When you upload a file whose name is already taken, Files asks whether to replace it or keep both, which saves the new one as `name (2).ext`. The agent gets a different protection. It remembers which version of a file it last read, and if you edit the file after that, its next write is refused with "File changed since last read, re-read and retry" instead of replacing your edit.

## Reports, PDFs and Office files

The agent writes reports in Markdown and can export one, up to 256 KB of Markdown, as a designed PDF next to the source, attached to its reply by default. Keep charts as separate image files alongside the report. For Word, Excel and PowerPoint, it writes the file with Python in its terminal, which has python-docx, openpyxl and python-pptx installed, and uses LibreOffice to convert between formats. Our [browser and terminal guide](/blog/ai-agent-browser-and-terminal/) lists the full toolset and the five-minute command limit.

Incoming material follows the same rule. A file at an HTTPS link becomes a workspace file before the agent works on it, so the source of a comparison is in the folder next to the result.

## Apps the agent builds

Some output is better as a small tool than a document: a review queue, an intake form, a tracker people update. Construct can build a private workspace app for that. Its source lives in `Apps/<id>/` in Files and its saved records in `AppData/<id>/`, so the app's data is as visible as any other file.

Apps are the one kind of agent output with version history. Every successful build is kept, up to the last 10, and **Versions** in the app window's menu restores an earlier one. An app can be shared with the whole workspace, where a teammate's write through it asks them to confirm first, or by public link, which opens it read-only. ## How a team finds the work later

Three habits make a folder easy to search months later, and the product supports each one:

1. Keep one folder per job, with dated files inside it. `Team/clients/acme/reports/2026-11-16-weekly.md` sorts itself, and the agent can find last week's file by name without being told.
2. Search by name or by content. Files searches names. The agent's files tool can also search inside files, so "find the report that mentioned the Q3 discount" is a reasonable request.
3. Start from Activity when you need to know why a file exists. Each Activity row names the agent, what it did and the file path it touched, and **Open task** takes you to the conversation that produced it.

## Auditing what an agent did

Activity is the record of what agents did: one row per action, with the agent, the action, a short reason, whether it succeeded, and the subject, such as a file path, a search query or a URL. It deliberately does not store tool inputs and outputs, so the content of a file lives in Files, not in the log. Rows are kept for 30 days or until a person's rows pass 10 MB, and you can export them as CSV or JSON, up to 50,000 rows at a time. Activity is per person: you see the rows for your own runs, and there is no workspace-wide feed of every member's agents. Our [activity log guide](/blog/ai-agent-activity-log/) compares this with a full audit log.

For anything you need beyond 30 days, the files are the durable evidence. That is another reason to have the agent save its inputs (the downloaded source, the raw CSV) next to its outputs rather than only the final summary.

## Deletes are permanent and overwrites are final

Files has no trash and no version history. Deleting a file in the Files app shows "This can't be undone. Agents that use these files will no longer find them." A folder is deleted with everything inside it. When the agent deletes a file with its files tool, it is removed the same way, without a confirmation step. An overwrite replaces the previous contents.

Three practices cover most of the risk:

- Write a new dated file each run instead of overwriting one file.
- Tell the agent in a standing instruction not to delete anything in a given folder; our guide to [what your AI agent can delete](/blog/what-can-your-ai-agent-delete/) covers the rest.
- Keep final copies where your team already backs up work, such as a connected Google Drive, and use Files for the working set.

When a member leaves a workspace, their private files are kept, and inviting them back restores access. Deleting a workspace or closing an account deletes its files, so download what you need first.

## Storage and who pays for it

Storage counts against the workspace owner's plan: 100 MB on Lite, 1 GB on Starter and 3 GB on Pro ([pricing](/pricing/)). The total covers every workspace that person owns, plus attachments on email the agents send. When it is full, writes are refused with a message saying so; nothing is deleted to make room. PDFs and images fill 100 MB quickly, so a team archiving weekly reports for several clients will want Starter or above.

## Setting up a weekly report folder

Here is a request that leaves a clean history behind. Adjust the folder and the data source to your own:

<Prompt label="Weekly report that builds on itself">

Every Monday at 8am, for each client folder in Team/clients, read the most recent file in reports/, pull this week's numbers from the connected analytics app, save them to data/YYYY-MM-DD.csv, and write reports/YYYY-MM-DD-weekly.md comparing the two weeks. Export the report to PDF in the same folder. Never overwrite or delete an existing file in Team/clients. Post a one-line summary per client to me in chat. Do not email clients.

</Prompt>

After a month, each client folder holds four dated reports, four PDFs and four CSVs, and next month's run compares against what was actually sent. An account manager who edits a report before sending it does not lose the edit to the next run, because each run writes a new dated file.
